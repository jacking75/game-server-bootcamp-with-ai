## T3. 학습용 CLAUDE.md (C# 버전)

> 이 템플릿은 Claude Code 기준 예시다. Codex CLI 등 다른 코딩 에이전트를 쓴다면 해당 도구의 지침 파일(예: `AGENTS.md`)에 동일한 내용을 작성하면 된다.

```markdown
# 프로젝트: <이름> (학습용)

## 목적
이 프로젝트는 학습 과제다. 코드의 완성보다 학습자(나)가 모든 코드를 이해하는 것이 우선이다.

## 환경
- Windows 11, .NET 10 SDK, Visual Studio 2026 / VS Code
- 테스트: xUnit. 벤치마크: BenchmarkDotNet (Release만)
- Docker 사용 안 함. CI 사용 안 함(로컬 스크립트로 빌드·테스트). 기본 DB는 SQLite(파일 기반), 선택 시 MySQL 8(Repository 인터페이스 + DI로 구현체 교체). Redis는 redis-windows(https://github.com/redis-windows/redis-windows)를 로컬에서 실행

## 구조
- src/<Project>.Net : 네트워크 계층 (세션, 송수신)
- src/<Project>.Logic : 게임 로직 (룸, 유저, 매칭) — 소켓 참조 금지
- src/<Project>.Rules : 게임 규칙 — 외부 의존 없음
- tests/ : 단위·통합 테스트
- docs/ : DESIGN.md, PROTOCOL.md, adr/

## 코딩 규칙
1. nullable 활성화, 경고는 오류로 취급
2. async 메서드는 Async 접미사, async void 금지
3. 공유 상태는 소유자를 주석으로 명시. 룸 로직에는 lock 금지(Job 큐로)
4. 소켓 버퍼는 반드시 풀에서 빌리고 반환
5. 예외는 경계(핸들러 진입점)에서만 잡고 Serilog로 로그

## 에이전트 행동 규칙 (학습 목적)
- 코드를 생성할 때 각 클래스/주요 함수에 "왜 이렇게 설계했는지" 한 줄 주석을 단다
- 한 번에 파일 하나만 만든다. 다음 파일로 넘어가기 전에 멈춘다
- 내가 이전 작업에 대한 설명 없이 다음 작업을 지시하면, 이전 작업의 핵심을 1문장 질문으로 확인한 뒤 진행한다
- 새 NuGet 패키지를 추가할 때 선택 이유와 대안 1개를 함께 적는다
- 테스트 없이 기능 코드를 완료로 보고하지 않는다
- 내가 "결함 주입" 모드를 요청하면 정답 위치는 "정답 공개" 전까지 절대 말하지 않는다
- 내가 설계 문서를 첨부하면 문서와 다른 구조를 제안하기 전에 먼저 차이를 지적한다
```

## T3'. 학습용 CLAUDE.md (C++ 버전) — 차이 나는 부분만

```markdown
## 환경
- Windows 11, Visual Studio 2026 (MSVC, C++20/23), CMake 3.28+, vcpkg 매니페스트 모드
- 테스트: GoogleTest. 벤치마크: Google Benchmark (Release만). ASan은 Debug 구성에서 상시
- 네트워크: Winsock2 + IOCP 직접 구현 (Boost.Asio 사용 금지 — 비교용 별도 프로젝트 제외)

## 코딩 규칙
1. /W4 /permissive-, 경고는 오류로
2. new/delete 직접 호출 금지. unique_ptr 기본, shared_ptr은 소유권 공유가 필요한 경우만 주석과 함께
3. 모든 OVERLAPPED/WSABUF가 가리키는 버퍼의 수명은 완료 통지 이후까지 보장 (소유자 명시)
4. 룸 로직에 mutex 금지(Job 큐로). atomic 사용 시 memory_order 선택 근거 주석
5. UB 후보(초기화 안 된 읽기, 부호 오버플로, 댕글링)는 리뷰에서 최우선

## 에이전트 행동 규칙 추가
- 새 vcpkg 의존성 추가 시 이유·대안·빌드 시간 영향을 적는다
- Win32 API를 쓸 때 실패 시 GetLastError/WSAGetLastError 처리를 빠뜨리지 않는다
```
